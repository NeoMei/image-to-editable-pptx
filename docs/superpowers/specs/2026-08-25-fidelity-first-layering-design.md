# 图片式 PPT 保真优先分层设计

## 1. 决策与背景

本设计替代原型中“识别到的面板、色条、文字和图标全部移除，再用万相一次性重绘大面积背景”的策略。

真实第 7 页验收暴露了两个事实：

1. Qwen3-VL 的定位坐标是 `[0, 999]` 归一化坐标，必须换算到原图的 1280×720 像素坐标；错误地按像素解释会导致文字重复、图标错位和遮罩扩大。
2. 将多个面板、色条、文字和图标合并成大遮罩交给 `wanx2.1-imageedit`，会生成伪文字、网页结构和新图形。即使 API 调用成功，也无法满足幻灯片保真要求。

经确认，本阶段采用“保真优先、文字第一”的产品取舍：

- 所有可靠 OCR 文字应成为可编辑文本框；
- 面板、色条、边框、阴影、纸张纹理和小装饰保留在背景；
- 主要图标仅在分割与重组质量达标时成为可移动位图；
- 不以图层数量作为成功指标；
- 最坏结果应是某个元素不能编辑，而不是画面被生成式幻觉破坏。

## 2. 目标与非目标

### 2.1 目标

- 第 7 页肉眼观感接近源图，同时 10 段 OCR 文字成为独立文本框。
- 在不降低保真度的前提下，尽可能拆出主要图标组合。
- 每个候选元素能够独立接受、回退和记录原因。
- 背景修复是局部、确定性、可验证的；遮罩之外的像素保持不变。
- 最终 PPTX 经过重新渲染、越界检查和全尺寸人工对比。

### 2.2 非目标

- 不把面板、色条、边框、阴影或纹理重建为 PowerPoint 原生形状。
- 不保证每个图标都可编辑。
- 不拆解插画内部路径、渐变或零件。
- 不追求与 Canva Magic Layers 相同的全场景能力。
- 第 7 页首轮验收不使用生成式背景修复。
- 本阶段不做整套 PPT 批处理、交互式校正界面或新增云端服务。

## 3. 总体架构

流水线分为分析、候选、试拆、验证和发布五个阶段：

```text
源 PNG
  -> OCR 文字分析
  -> 视觉模型提出主要图标候选
  -> 候选按优先级排序：文字优先，图标其次
  -> 每个候选独立试拆
       -> 生成紧边界遮罩
       -> 提取可编辑层
       -> 在原背景上执行局部确定性修复
       -> 将元素重新叠回并与源图比较
       -> 通过则接受；失败则撤销该候选
  -> 用已接受候选生成最终背景与图层清单
  -> 原子导出 PPTX、账本和 QA 产物
```

关键架构约束：

- 候选判断与最终发布分离。试拆失败不得污染后续候选的源数据。
- 每个候选始终从同一份源图和当前已接受背景派生，不从失败结果继续加工。
- 面板、色条等背景家具不会进入移除遮罩。
- 不再把多个候选合并后交给生成模型一次处理。
- 最终输出只有全部必需产物和 QA 检查通过后才替换上一个成功版本。

## 4. 坐标与分析契约

### 4.1 OCR

- `qwen3.5-ocr` 返回的四点位置使用原图绝对像素坐标。
- OCR 是文字内容和文字位置的权威来源。
- OCR 越界框继续由规划层裁剪并记录 `out_of_bounds_clipped`。

### 4.2 视觉模型

- `qwen3-vl-plus` 的边界框使用 `[0, 999]` 归一化坐标。
- 解析器按以下规则换算：
  - `x_px = round(x_norm / 1000 * 1280)`；
  - `y_px = round(y_norm / 1000 * 720)`。
- 视觉文字候选不得覆盖 OCR；只要与 OCR 框达到去重交并比阈值，就丢弃视觉文字候选。
- 视觉模型只负责提出主要图标组合，不负责决定某个候选必然可拆。

## 5. 文字拆分

### 5.1 候选与图层

- 每个 OCR 行或经现有规则合并后的段落生成一个文本候选。
- 文本内容、位置和换行来自 OCR。
- 字号、颜色和对齐沿用现有确定性估算；字体仍使用可用的中文回退字体。
- 第 7 页预期生成 10 个文本图层。

### 5.2 文字遮罩

- 遮罩只覆盖紧贴文字的区域，不扩展到所在面板或色条。
- 默认水平和垂直 padding 分别受文字框高度约束，不能连接到相邻图标、边框或其他文字。
- 当两个文字框的扩展遮罩会相连时，分别处理并限制 padding，而不是合并成大块。

### 5.3 文字背景修复

- 先识别文字所在的局部表面颜色和纹理。
- 采样区域必须位于同一连通表面，并排除其他文字、边框和图标遮罩。
- 使用邻近相似纹理块或局部颜色模型填充文字空洞。
- 遮罩之外的像素逐字节不变。
- 若找不到安全采样区域，则该文字标记为 `repair_unavailable`，整页不发布为成功结果；文字是本阶段的必需能力，不允许静默保留双重文字。

## 6. 主要图标拆分

### 6.1 分组原则

主要图标按视觉语义组合处理，不拆内部零件。第 7 页的候选示例包括：

- 眼睛与雷达图；
- 扳手与安全盾牌；
- 双气泡；
- 插头与插座；
- 闪电与时钟。

视觉模型可以提出更细的框，规划层应在同一面板内根据距离、重叠和语义标签合并成稳定组合。

### 6.2 提取与透明化

- 从源图的紧边界框提取候选，不从修复背景或其他中间图提取。
- 使用边缘连通背景移除生成 alpha。
- 不允许把矩形裁剪作为可发布的可编辑图层；`rectangular` 只能作为诊断产物。
- 背景颜色不一致、主体接触裁剪边缘、前景被过度擦除或 alpha 覆盖异常时，候选直接回退。

### 6.3 图标接受门槛

图标只有同时满足以下条件才接受：

- extraction 为 `transparent`；
- alpha 前景占裁剪面积处于合理范围，既不是空图也不是近乎整块不透明；
- 裁剪边界没有连续的大面积不透明像素；
- 主体没有被裁断；
- 将图标叠回局部修复背景后，扩展框内的结构相似度达到实现计划规定的高门槛；
- 重组图像中不存在明显矩形边缘、色块或文字破坏；
- 与 OCR 文字框不存在破坏性重叠。

任一门槛失败时：

- 不修改背景；
- 不创建该图标图层；
- 在账本中记录稳定的回退原因；
- 继续处理其他候选。

## 7. 确定性背景修复

### 7.1 默认策略

第 7 页首轮使用本地确定性局部修复，不调用万相：

1. 为单个候选创建小遮罩。
2. 在遮罩外围建立采样环。
3. 按颜色距离、局部方差和边缘连续性筛选同表面像素或纹理块。
4. 从距离近且统计特征相似的有效区域复制或合成填充值。
5. 仅写入遮罩内部。
6. 对修复区执行接缝、高对比残留和异常纹理检查。

面板、色条和底部深蓝条保留在源背景，因此修复算法只需处理其内部的小型文字或图标空洞，不需要重新创造这些结构。

### 7.2 生成式修复边界

万相保留为显式可选能力，但不属于第 7 页首轮验收路径：

- 默认关闭；
- 只允许处理单个、小面积、不规则空洞；
- 每次调用只包含一个候选；
- 结果仍须通过与确定性修复相同的重组验证；
- 失败时回退到“不拆该候选”，不得发布生成式幻觉。

## 8. 质量验证

### 8.1 自动验证

- `outside_mask_unchanged`：候选遮罩外像素必须逐字节相同。
- `repair_has_no_high_contrast_residue`：修复区不得残留明显字形、线条或新高对比组件。
- `no_rectangular_asset_background`：可发布图标必须为透明提取。
- `recomposition_similarity`：把已拆元素叠回后，与源图的局部相似度达到高门槛。
- `required_text_count`：第 7 页必须输出 10 个文本图层。
- `pptx_structure`：至少包含 1 个背景图层和 10 个文本图层。
- `no_overflow`：最终 PPTX 通过幻灯片边界检查。
- `atomic_publication`：失败运行不覆盖上一个成功结果。

相似度的具体数值将在实施计划中用源图、现有坏例和离线 fixture 校准；门槛必须先通过测试固定，再用于生产代码，不能在真实运行后随意放宽。

### 8.2 人工验收

- 重新渲染最终 PPTX，而不是查看中间 PNG。
- 以全尺寸并排比较源图和最终渲染图。
- 检查文字位置、字号、换行和颜色。
- 检查面板、色条、纹理、阴影和页脚是否保持原样。
- 检查图标边缘、矩形底、接缝、伪文字和新图案。
- 在 PowerPoint 或 WPS 中实际移动至少一个已接受图标并修改至少一段文字。

## 9. 账本与错误处理

每个候选在 run ledger 中记录：

- `candidateId`、类型、原始边界框和组合关系；
- `decision`：`accepted` 或 `kept_in_background`；
- `repairMethod`；
- extraction 类型；
- 质量指标；
- 稳定的回退原因；
- 最终图层路径或背景保留状态。

错误处理遵循以下规则：

- 单个图标失败只回退该图标。
- 任一必需文字无法安全修复时，整页构建失败。
- 失败运行保留在 `.failed-runs`，上一个成功目录保持不变。
- API Key、Authorization、签名 URL 和 DashScope 头不得进入日志、账本、录制或 Git。

## 10. 第 7 页完成定义

同时满足以下条件才视为完成：

1. OCR、视觉分析和坐标换算使用真实百炼接口成功运行。
2. 最终 PPTX 含 10 个独立可编辑文本框。
3. 面板、色条、边框、阴影和纹理保持源图观感。
4. 可发布图标均为通过质量门槛的透明组合；0 个图标通过仍可接受。
5. 不出现伪文字、新物体、矩形底或明显修复接缝。
6. 遮罩之外像素不变，自动测试、类型检查、构建和编译测试全部通过。
7. 最终 PPTX 重新渲染后通过全尺寸人工对比。
8. 在 PowerPoint 或 WPS 中完成文字修改和已接受图标移动的实际操作验收。
