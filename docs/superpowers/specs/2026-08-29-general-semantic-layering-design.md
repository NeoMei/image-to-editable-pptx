# 通用 PPT 图片语义分层设计

## 1. 决策与背景

本设计将 Image to Editable PPTX 从“文字优先，只拆可靠的完整图标”升级为通用语义分层工具。新能力不得针对某一张幻灯片写死物体名称、坐标、颜色或组合规则；《深入理解 AI-Agent》第 7 页只是回归样例之一。

已确认的产品取舍：

- 支持任意内容、任意宽高比的 PPT 图片，不再限定 1280×720。
- 输入支持 PNG 和 JPEG/JPG；其他格式明确拒绝并建议转为 PNG。
- OCR 文字仍是必需的可编辑层。
- 能够独立移动的对象应尽量拆分；由连线、箭头或共享轮廓构成的不可分单元保持为复合层。
- 文字色块、标签、栏和其他底板优先输出为保真透明 PNG，与可编辑文字分层。
- 未遮挡对象使用本地确定性方法提取；只对确实被其他对象遮挡的缺失区域调用托管图像编辑 API 做最小补全。
- 任何不可验证的候选层保留在背景；不以图层数量换取伪造内容。

本设计扩展但不取消 2026-08-25-fidelity-first-layering-design.md 中的保真优先、文字优先、原子发布和失败回退原则。

## 2. 目标与非目标

### 2.1 目标

- 将普通 PPT 导出图、截图或图片式页面转换为保持原宽高比的单页 PPTX。
- 识别独立前景对象、复合对象、连接符号、文字底板和遮挡关系。
- 将可靠的对象和无字底板输出为可移动、可缩放的透明 PNG 层。
- 将底板中的文字移除并修复底色，同时保留对应的可编辑文字层。
- 只在遮挡导致对象移动后必然暴露缺口时，对遮挡区做有限生成式补全。
- 产生可追溯的场景图、候选决策、生成区域记录、重组预览和图层展开预览。
- 保持 build 的离线性：给定完整分析包后，构建 PPTX 不读取云端凭证，不发起网络请求。

### 2.2 非目标

- 不保证任意复杂场景都能完全拆解。
- 不在首版中把底板重建为可改颜色的 PowerPoint 原生形状。
- 不进行无上限的递归子对象分析。
- 不在用户机器上部署或运行大型分割、OCR 或图像生成模型。
- 不在本阶段增加整套 PPT 批处理队列或人工拖拽修正 UI。

## 3. 输入、画布与输出契约

### 3.1 输入格式

- 接受 PNG、JPEG 和 JPG 扩展名，但必须以魔数和解码结果为准，不信任扩展名。
- 解码后统一转换为无损 RGBA 工作画布；JPEG 压缩噪声只影响提取容差，不改变其他质量门。
- 不限定常见幻灯片宽高比。默认安全边界为：文件不超过 50 MiB，宽高各至少 64 px 且不超过 8192 px，总像素不超过 40,000,000，长短边比例不超过 56:1。
- 超出边界的输入在任何 API 调用前失败，不产生部分输出。

### 3.2 坐标与 PPT 尺寸

- 内部场景图使用 [0, 1] 归一化坐标；提取和像素校验转换为当前工作画布的绝对坐标。
- 导出 PPTX 时保持原宽高比：通常将较长边映射为 13.333 英寸；若短边因此小于 1 英寸，则将短边设为 1 英寸并按比例计算长边。56:1 的输入比例上限保证两边均处于 1–56 英寸的输出安全范围。
- 文字、底板、对象和背景使用同一坐标变换，不对不同层分别缩放。

### 3.3 输出

- 输出单页 PPTX、场景图、manifest v2、run ledger、净背景、透明资产、移除遮罩和 QA 预览。
- manifest v2 为资产增加 role、groupId、provenance、relations 和 reviewRequired 字段。
- 读取端继续接受 manifest v1；新构建默认输出 v2，不就地改写旧成功目录。

## 4. 通用语义场景图

### 4.1 节点

场景图节点的通用角色：

- background：整体画布和不安全的剩余像素。
- text：OCR 权威文字。
- text-backing：承载一个或多个文字的独立图形或色块。
- foreground-object：可能独立移动的视觉对象。
- connector：线、箭头、引导轨迹或其他关系标记。
- compound-group：语义上必须一起移动的节点集合。
- decoration：小型装饰、纹理或不值得独立编辑的元素。

每个节点包含稳定 ID、角色、归一化边界框、置信度、预估 z-order、提取提示和模型可读 label。label 仅用于审计和人工检查，不得成为业务分支条件。

### 4.2 关系

场景图支持：

- belongs-to：子节点属于复合组。
- connected-to：节点由连接符号绑定。
- carries-text：底板承载 OCR 文字。
- occludes：前景节点遮挡另一节点。
- in-front-of 和 behind：显式层级关系。

规划器依据关系图判断拆分与合并。“同一面板”不能成为合并理由；强几何重叠只用于合并重复检测，不能把相邻独立对象强制组合。

## 5. 两阶段视觉分析

### 5.1 整页分析

每页默认执行一次整页 OCR 和一次整页 Vision 场景图分析。Vision 区分独立对象、复合组、底板、连接符号和遮挡关系，但不直接决定候选必然可发布。

### 5.2 局部复核

- 只对标记为复合、存在遮挡、关系矛盾或边界不完整的候选发起局部 Vision 请求。
- 每页最多 8 次局部 Vision 请求，可向下调整或关闭，不允许无界递归。
- 局部请求只发送带小范围上下文的裁剪图，并把返回坐标映射回全局场景图。
- 局部结果只能细化目标子图，不能覆盖无关 OCR 或全局节点。

## 6. 候选规划与提取

### 6.1 普通前景对象

- 始终从原始无损工作画布提取，不从修复图或其他候选的中间结果提取。
- 结合语义框、局部颜色、边缘和连通区域生成 alpha 蒙版。
- 使用渐进式裁剪搜索获得完整边缘，并保留去底色污染的半透明抗锯齿像素。
- 独立对象分别发布；只有关系图确认必须共同移动时才发布复合资产。

### 6.2 文字底板

- carries-text 关系确定底板与 OCR 文字的对应。
- 底板蒙版必须覆盖完整轮廓，但不能吸收相邻面板、背景纹理或无关图标。
- 在底板资产内部对关联 OCR 紧蒙版执行同表面局部修复，生成无字底板。
- 底板资产和可编辑文字分别发布，并保留 carries-text 关联。
- 纯色、渐变和轻微纹理底板均可尝试；文字残留、边缘污染或修复失败时整个底板回退到背景。

### 6.3 遮挡对象

- 只有场景图存在置信度达标的 occludes 关系，且本地蒙版证明被遮挡对象的轮廓在遮挡边界处被截断时，才进入补全。
- 已可见像素是不允许修改的保护区；图像编辑 API 只可写入由遮挡关系导出的隐藏区蒙版。
- 每次请求只处理一个候选的局部裁剪；每页最多 4 次遮挡补全，可关闭或向下调整。
- 核心使用插拔式 provider 接口，默认实现使用现有阿里云图像编辑 provider；核心规划器不判断特定物体名称或模型名。
- 补全资产的 provenance 必须分别记录原图可见像素和生成隐藏像素的蒙版、模型 ID、任务 ID 和哈希。

## 7. 背景修复与图层次序

- 背景从原始工作画布派生，仅移除最终接受的文字、底板和对象蒙版。
- 某个候选失败时，其像素不进入最终移除蒙版，不得污染后续候选。
- 默认顺序为：净背景 → 被遮挡对象 → 其他前景对象 → 遮挡者 → 文字底板 → 可编辑文字。
- 实际顺序优先遵循 in-front-of 和 behind 关系；循环或矛盾关系使相关候选保留背景，不猜测层级。
- 底板必须在其 carries-text 文字之下；未知层级不得通过 label 猜测。
- 若文字底板与无明确层级关系的前景对象发生实质重叠，该底板保留在背景，不使用默认顺序强行发布。

## 8. 网络阶段与 CLI 行为

- run 编排整页 OCR、整页 Vision、按需局部 Vision、有限遮挡补全和本地构建。
- analyze 执行全部网络阶段，包括局部 Vision 和启用时的遮挡补全，并写入自包含分析包。
- build 只读取已验证分析包中的场景图、蒙版、补全资产和 provenance，全程离线。
- 默认局部 Vision 上限为 8，遮挡补全上限为 4。CLI 只提供向下调整和完全关闭选项，不提供无上限模式。
- 每次网络请求在 ledger 中记录模型、耗时、裁剪哈希和脱敏任务元数据，不记录凭证或带签名 URL。

## 9. 质量门与 QA 产物

### 9.1 自动质量门

每个候选必须通过：

- alpha 前景比例、不透明边界、抗锯齿边缘和主体完整性检查；
- 与无关 OCR 文字的重叠检查；
- 背景修复的遮罩外逐字节不变检查；
- 所有已接受层按 z-order 叠回后的整页重组误差门；
- 底板内部的字形残留、白边和高对比接缝检查；
- 遮挡补全的可见像素锁定、生成蒙版越界和轮廓连续性检查。

生成补全中无法从原图验证的隐藏像素必须标记 reviewRequired: true；不能仅因正常重组图与原图相同就声称隐藏部分已验证。

### 9.2 QA 产物

每次成功构建输出：

- recomposition-preview.png：正常层级重组图。
- layer-review.png：棋盘格背景上的单层联系表。
- exploded-preview.png：对象错位展开图，用于检查遮挡补全、文字残留和对象完整性。
- scene-graph.json：已验证节点与关系。
- run-ledger.json：分析、提取、补全、验证和发布的完整决策。

## 10. 通用测试与人工验收

### 10.1 自动测试

- 输入契约覆盖 PNG、JPEG、伪扩展名、损坏文件、安全边界和解压炸弹。
- 画布契约覆盖 16:9、4:3、竖版、正方形和超宽图片。
- 场景图 fixture 覆盖独立、相邻、重叠、传递重叠、连接、嵌套、遮挡和矛盾 z-order。
- 底板 fixture 覆盖纯色、渐变、纹理、中英文混排、多行文字和修复失败回退。
- 遮挡 fixture 覆盖可见区被修改、生成区越界、轮廓不连续、provider 失败和用量上限。
- 测试源代码扫描不得出现依赖第 7 页对象 label、绝对坐标或颜色的业务分支。
- manifest v1 向后兼容、manifest v2 导出、原子发布、失败运行保留、脱敏和离线 replay 必须继续通过。

### 10.2 真实图片验收

验收集至少包含：

- 扁平图标、文字底板和小面积遮挡页面；
- 不同尺寸和宽高比页面；
- JPEG 压缩页面；
- 纯色、渐变和纹理底板页面；
- 无法安全拆分、应整体回退的负样例。

每个真实验收页必须检查最终 PPTX 渲染图、layer-review.png 和 exploded-preview.png。至少选择一页在 WPS 中实际移动前景对象、移动文字底板、修改可编辑文字并撤销，明确处理保存、放弃和重新打开结果。

## 11. 安全、隐私与成本

- 整页图片只发送给整页 OCR 和 Vision provider。
- 局部复核和遮挡补全只发送最小必要裁剪。
- API Key、Authorization、带签名 URL、DashScope 头和不透明 token 继续使用递归脱敏和 0600 写入策略。
- ledger 记录请求数和模型 ID，但不虚构固定单页成本。
- 默认每页最多 1 次 OCR、1 次整页 Vision、8 次局部 Vision 和 4 次遮挡补全；实际只对需要复核或补全的候选调用。

## 12. 完成定义

以下条件全部满足才视为完成：

1. 核心规划和提取不依赖任何验收页的特定 label、坐标、颜色或对象名。
2. PNG 和 JPEG/JPG 在任意受支持尺寸与宽高比下使用同一流水线。
3. OCR 文字、独立对象、复合对象、文字底板和遮挡关系有明确通用契约。
4. 未遮挡对象不使用生成式编辑；遮挡补全不能修改原图可见像素。
5. 底板与文字分层后无双重文字、残留字形、白边或明显修复接缝。
6. 所有接受层重组后通过整页保真门；不可靠候选安全地保留背景。
7. 补全的隐藏像素在 manifest 和 ledger 中显式标记，并通过图层展开预览人工检查。
8. build 保持离线，分析包哈希、原子发布、脱敏和失败运行保留契约继续成立。
9. 源测试、编译产物测试、类型检查、构建、PPTX 边界检查和真实图片验收全部通过。
10. 至少在 WPS 中完成一次真实文字、底板和前景对象编辑操作，撤销后处理并确认重新打开结果。
