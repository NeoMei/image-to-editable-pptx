# 图片式 PPT 增强可编辑原型设计

## 目标

把仅含整页位图的 PPT 页面恢复为可在 PowerPoint/WPS 中编辑的 PPTX。首个原型只处理《深入理解 AI-Agent》讲义第 7 页，验证文字、主要图形、图标和背景能否通过阿里云现成 API 与轻量本地代码重建。

## 范围

首版必须做到：

- 全部文字恢复为独立文本框；
- 顶部标签、橙色横条、四个内容区域和底部横条恢复为原生 PPT 形状；
- 眼睛、扳手、对话气泡、插头、闪电和时钟恢复为可移动图片元素；
- 移除文字和主要对象后生成干净背景；
- 输出 PPTX 可由 PowerPoint 和 WPS 正常打开；
- 用户侧不部署模型，不需要 GPU。

首版不做：

- 把插画内部的每条描边还原成矢量路径；
- 还原原作者使用的精确字体文件；
- 一次处理整套 15 页；
- 建立网页端、账号系统、队列或计费系统。

## 输入现状

源文件共有 15 页，每页只有一张覆盖 1280×720 画布的位图，没有原生文本框、形状或图表。第 7 页同时包含多类文字、规则面板、纯色色块和不规则图标，适合作为增强版验收样本。

## 技术方案

### 1. 阿里云百炼 OCR

使用 `qwen3.5-ocr` 的 DashScope 原生接口执行 `advanced_recognition`，从 `ocr_result.words_info[]` 获得文本行及四点坐标。`text_recognition` 只返回纯文本，不满足本原型的坐标契约。调用使用 Base64 Data URL，避免额外部署 OSS。

### 2. 阿里云百炼视觉理解

使用视觉模型分析同一页面，严格输出 JSON：

- `type`: `text | panel | shape | icon | illustration | photo | background`
- `bbox`: `[x1, y1, x2, y2]`
- `label`: 元素语义
- `zIndex`: 推测层级
- `editableAs`: `text | native-shape | bitmap | background`
- `fillColor`、`strokeColor`、`cornerRadius`: 能可靠判断时输出

视觉结果只负责候选元素和语义，不覆盖 OCR 的文本内容与坐标。

### 3. 统一元素规划

元素规划器执行确定性合并：

- OCR 文本优先；
- 与文字框重叠的视觉 `text` 候选被丢弃；
- 高置信度规则矩形转为原生 PPT 形状；
- `type=background` 或 `editableAs=background` 的视觉候选只是背景语义，不进入前景 asset 与 removal mask；
- 插画、图标和照片保留为位图元素；
- 相邻 OCR 行仅在垂直间隔为 0 到较小行高的 75%（最少 4 px）、左边对齐误差不超过较小估算字号的 50%（最少 4 px）、且估算字号比不超过 1.2 时合并；文本以换行连接，坐标使用所有原始行的并集；
- 全部坐标从 1280×720 像素映射到 13.333×7.5 英寸。

统一中间格式保存为 `manifest.json`，使 API 调用、图像处理和 PPTX 导出可分别测试。

### 4. 对象提取

原型优先使用轻量本地算法：

- 按视觉模型 bbox 裁剪对象；
- 对近似米白背景执行边界连通的颜色去除，生成透明 PNG；
- 对不能可靠去背景的照片保留矩形裁剪；
- 透明结果不合格时回退为矩形图片，不伪造轮廓。

阿里视觉智能通用分割保留为可插拔增强项，不作为第一个可运行版本的硬依赖，以免额外要求 AccessKey/Secret 与第二套鉴权。

### 5. 背景补全

根据全部文字框、已提取对象和可重建形状生成一张合并 mask；一次调用 `wanx2.1-imageedit` 的 `description_edit_with_mask`：

- 白色区域：需要移除并补全；
- 黑色区域：保持原图；
- 提示词要求延续米白纸张纹理并移除标记区域内的文字、图标和边框。

如果万相失败，原型明确失败，不使用带有重复文字的原图冒充干净背景。

### 6. PPTX 重建

使用开源 `PptxGenJS` 生成 16:9 PPTX：

1. 放置万相生成的干净背景；
2. 按 zIndex 放置原生形状；
3. 放置透明或矩形位图对象；
4. 最后放置可编辑文本框；
5. 原生形状在 manifest 保留视觉语义 `label`，PPTX 对象名同时写入 id 与 label，便于在选择窗格中辨认。

## 配置

原型只要求：

- `DASHSCOPE_API_KEY`
- `DASHSCOPE_WORKSPACE_ID`

北京地域服务地址由工作空间 ID 组成。模型 ID、超时、轮询间隔和输出目录允许通过配置文件覆盖，但不允许把密钥写入仓库。

## 失败处理

- API 未配置：启动前失败并列出缺失变量；
- OCR 或视觉 JSON 不合法：在规范化前保存递归脱敏的原始响应与解析错误，停止当前页面，并在 staging 失败时一起留存；
- bbox 越界：裁剪到画布并记录告警；
- 万相超时或失败：保留任务 ID 与响应，停止导出；
- 对象透明化质量不足：回退为矩形裁剪并记录 `fallbackReason`；
- 字体缺失：使用配置中的中文回退字体并记录替换。

## 验收标准

- 原始图片中的文字不在背景中残留或重影；
- OCR 文本与原页面逐项核对，无明显漏字；
- 文本框位置与原图对应区域的边缘偏差不超过 8 像素；
- 顶部标签、橙色横条、四个内容区域和底部横条可独立改色；
- 六类主要图标可以独立移动和缩放；
- 移走对象后背景没有明显矩形洞或重复对象；
- 导出的 PPTX 在 PowerPoint/WPS 中正常打开；
- 所有网络调用均为阿里云中国地域 API，用户机器不运行模型。

## 后续扩展

原型通过后再依次增加：阿里通用分割提供器、整套 PPT 批处理、人工校正界面、供应商适配层和火山引擎后备实现。
