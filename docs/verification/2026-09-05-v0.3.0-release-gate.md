## Reproduced routing blockers

Independent review findings were reproduced again by the main agent with
injected responses, without network calls or credentials:

1. **P1 — failed/filtered OpenAI API responses accepted.**
   `src/providers/provider-adapters.ts` parses valid output JSON without checking
   the response envelope status. HTTP 200 responses with `status: "failed"`, or
   `status: "incomplete"` plus `incomplete_details.reason: "content_filter"`,
   carrying `{"lines":[]}`, return `ok: true, validated: true`.
   Validate terminal envelope state and filtering before accepting payload text.
2. **P2 — explicit upstream disconnect blocks fallback.**
   `src/providers/opencodex-bridge.ts` maps an SSE `response.failed` event with
   `error.type: "upstream_error", error.code: "upstream_reset"` to
   `invalid_output`. The installed OpenCodex relay emits that envelope on a
   stream transport failure. The router therefore stops instead of advancing.
   Classify the explicit transport failure appropriately; unexplained truncated
   or malformed output must remain terminal.
